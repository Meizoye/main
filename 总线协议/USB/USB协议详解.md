# USB协议详解

## 1 核心概念

### 1.1 USB协议概述

USB（Universal Serial Bus，通用串行总线）是由Intel、Microsoft等公司在1996年推出的外部总线标准，旨在简化PC外设连接。

核心特点：

1. 即插即用：自动识别设备，无需手动配置
2. 热插拔：无需关机即可插拔设备
3. 统一接口：一种接口连接多种设备
4. 供电能力：提供5V电源（USB 2.0最大500mA，USB 3.0最大900mA）
5. 高速传输：USB 3.2 Gen 2x2最高20Gbps

### 1.2 USB版本对比

| 版本          | 发布年份 | 最大速率 | 功率 | 典型应用        |
| ------------- | -------- | -------- | ---- | --------------- |
| USB 1.0       | 1996     | 1.5Mbps  | 2.5W | 键盘、鼠标      |
| USB 1.1       | 1998     | 12Mbps   | 2.5W | 音频设备        |
| USB 2.0       | 2000     | 480Mbps  | 2.5W | U盘、打印机     |
| USB 3.0       | 2008     | 5Gbps    | 4.5W | 移动硬盘        |
| USB 3.1 Gen 2 | 2013     | 10Gbps   | 100W | 显示器、SSD     |
| USB 3.2       | 2017     | 20Gbps   | 100W | 高速存储        |
| USB4          | 2019     | 40Gbps   | 240W | Thunderbolt兼容 |

## 2 物理协议

### 2.1 USB 2.0引脚定义

| Pin  | 名称 | 功能    |
| ---- | ---- | ------- |
| 1    | VBus | +5V电源 |
| 2    | D-   | 数据负  |
| 3    | D+   | 数据正  |
| 4    | GND  | 地线    |

### 2.2 **USB 3.0引脚定义**（增加）

- 5个超高速差分对（TX+/TX-、RX+/RX-）
- 向后兼容USB 2.0

### 2.3 USB信号编码


NRZI

### 2.4 USB字节序

LSB在前，MSB在后，即小端序

## 3 枚举过程

### 3.1 USB热插拔检测

当有低速设备插入时D-存在上拉电阻使得D-出现高电平识别为低速模式

当有全速设备插入时D+存在上拉电阻使得D+出现高电平识别为全速模式

当有高速设备插入时D+存在上拉电阻使得D+出现高电平识别为全速模式，再通过Chirp序列总线握手机制识别为高速设备

### 3.2 设备枚举

设备插入检测VBus电流变化并识别设备速度

Host复位设备拉低D+/D-至少10ms

Host向0地址发送GET_DESCRIPTIONER请求获取设备描述符，读取设备描述符前8字节，等待设备响应

Host向0地址发送SET_ADDRESS请求重新分配地址，设备地址更新为新地址

Host向新地址发送获取完整设备描述符请求和完整配置描述符请求，识别设备功能

Host向新地址发送SET_CONFIGURATION请求，设备进入配置状态，使能Port和Endpoint，此时可以进行传输

## 4 传输协议

USB的数据传输只能在Host和设备之间传输，任意两个设备或Host都无法进行通信。USB协议规定了四种数据传输方式：

(1)控制传输。主要用于主机对设备的检测和配置。

(2)中断传输。用来支持那些偶然需要数据通信，但服务时间受限制的设备。中断传输常常用在键盘、鼠标和游戏杆等设备上。

(3)批量传输。适合使用在时间不重要的场合。批量传输可以传输大量的数据而不会阻塞总线，因为它会让其他类型的传输先执行，以等待可以传输的时间，如用于磁盘操作。

(4)同步传输。适合用于以固定速率进行的传输，而且可以容忍偶尔的错误，如实时语音传输。

### 4.1 设备端点（Endpoint）

端点是USB设备数据传输的节点，它包含数据缓存区，控制寄存器及状态寄存器等。每个USB设备通常都有多个端点，每个端点用来控制不同的功能。由于Host必须要端点0作为控制传输，因此它是任何USB设备必须有的，除此之外USB设备几乎不需要其他控制端点。

### 4.2 设备描述符（Descriptioner）

Host是通过请求USB设备的一系列描述符获取设备信息的。现在USB设备定义了3种描述符：

（1）标准类型。用于提供设备的基本信息。标准类型的描述符主要有：设备描述符、配置描述符、接口描述符、端点描述符以及字符串描述符等。

设备描述符包含USB设备的一般信息，如：产商ID/产品序列号/设备类号/默认端点最大包长度/配置描述符的个数等；

配置描述符包含描述符长度/供电方式/最大功耗等；

接口描述符指此USB设备的功能，有几个功能就有几个接口描述符；

端点描述符是设备和主机之间通信的逻辑接口，除控制端口0外，其余端口都为单向端口；

字符串描述符是Unicode编码的厂商信息/产品信息/设备序列号信息等

（2）设备类别特定描述符。用于提供设备更详细的信息。如HID类（人机接口类）设备的类别特定描述符中的HID描述符和报表描述符，就可以用来描述设备究竟是一个鼠标还是一个键盘。如果是鼠标，则报表描述符的数据就是鼠标的按键和位移

（3）厂商特定描述符。也是用于提供设备的一些更详细信息，不过它是由厂商自己定义的

每个USB设备只能有一个设备描述符，设备描述符下可能包含多个配置描述符、接口描述符、端点描述符等

字符串描述符是可选的，它定义了可能用到的字符串，其他的描述符可以根据字符串描述符中相应的索引值来引用相应的字符串

### 4.3 USB包格式

USB信息包是USB传输数据组织的基本形式，它主要包含以下字段：

（1）SYNC字段，用于信息包的开始与同步，它由硬件自动处理。

（2）PID字段，信息包标识符（Packet Identifier，PID），信息包共有四种类型：令牌包、数据包、握手包和特殊包，四种类型共对应16个PID码。
（3）地址字段，用于指明USB主机究竟是要和哪个设备通信，设备的地址初始默认为0，主机会在设备检测阶段给设备分配一个地址。
（4）端点字段，用于指明USB主机究竟是要和设备的哪个端点进行通信。如前所述，一个设备可以有多个端点。
（5）帧号码字段，USB主机把USB总线上的实际数据传输按时间分割成一块块的帧（Frame）或微帧（Micro Frame）。对于全速和低速的设备，主机将传输分成1毫秒的帧，对于高速设备主机将传输分成125微秒的微帧。帧号码字段就是用于识别特定的帧或微帧，它由硬件自动处理。
（6）数据字段，为实际要传输的数据。
（7）校验字段，用于信息包的数据校验，它由硬件自动处理。

字段组成如下图所示：

```

		|		 |		ADDR								|
		|		 |	ADDR  ENDPOINT  |	FRAME NUM  	DATA 	|

```

### 4.4 USB包类型

#### 4.4.1 令牌包（token）

令牌包分为以下四类：

（1）IN：通知设备返回数据包
（2）OUT：通知设备接受数据包
（3）SETUP：通知设备接受数据包，用于设备控制。只使用DATA0包，且只发送到设备的endpoint
（4）SOF：广播发送，仅用于全速设备，主机以1ms/125us产生1个帧。每次帧开始都通过SOF先发送1个帧号

IN/OUT/SETUP包 : SYNC + PID（0x09/0x04/0x0d） + ADDR + ENDPOINT + CRC5

SOF包：SYNC + PID(0x05) + FRAME NUM + CRC5 

#### 4.4.2 数据包（data)

若每次发送的数据长度大于端点的容量则拆分为DATA0包和DATA1包交替传输，但同步传输时只发生DATA0包。

SYNC + PID + DATA + CRC16

PID域值：
DATA0(0x03)：偶数包
DATA1(0x0b)：奇数包
PID-SYNC(0x07)：高速设备的pid同步包
PID-SPL(0x0f)：高速设备分离包

#### 4.4.3 握手包（handshake)

SYNC + PID
PID域值：
ACK(0x02)：正确接收
NAK(0x0a)：忙
STALL(0x0e)：错误
NYET(0x06)：无响应

#### 4.4.4 特殊包（special)

PID域值：
PRE(0x0c): 前导包
ERR(0x0c)：错误包
SPLIT(0x08)：分裂事务
PING(0x04)：ping测试

### 4.5 事务类型

#### 4.5.1 setup事务

主机向设备发送控制命令
【正常/设备忙/设备出错】设置事务包含：
host->device：token-SETUP
host->device：data-DATA0
device->host：handshake-ACK/NAK/STALL

#### 4.5.2 datain事务

主机向从设备读取数据
【正常】输入事务包含：
host->device：token-IN
device->host：data-DATA0/DATA1
host->device：handshake-ACK

【设备忙】输入事务包含：
host->device：token-IN
device->host：handshake-NAK

【设备错误】输入事务包含：
host->device：token-IN
device->host：handshake-STALL

dataout事务

主机向从设备写数据
【正常】输出事务包含：
host->device：token-OUT
host->device：data-DATA0/DATA1
device->host：handshake-ACK/NAK/STALL

### 4.6 传输类型

#### 4.6.1 控制传输（control transfer）

##### 4.6.1.1 建立阶段

setup事务

##### 4.6.1.2 读/写/无

读：
datain事务xN
写：
dataout事务xN
无控制：
无

##### 4.6.1.3 状态阶段

读：
dataout事务
写：
datain事务

#### 4.6.2 中断传输

不支持PING
重传机制为传输错误3次以下重传，否则放弃传输
读：
datain事务xN
写：
dataout事务xN

#### 4.6.3 批量传输（bluk transfer）

用于打印机/大容量设备等
支持PING
重传机制为传输错误3次以下重传，否则放弃传输
读：
datain事务xN
写：
dataout事务xN

#### 4.6.4 同步传输

用于实时传输，如麦克风/喇叭/UVC摄像头等
没有握手机制，是不可靠传输，运行误码存在
读：
host->device：token-IN
device->host：data-DATA0/DATA1 xN
写：
host->device：token-OUT
host->device：data-DATA0/DATA1 xN
